# Обучение модели оценки стоимости квартир

## Данные и постановка задачи

Для обучения используется таблица `real_estate_dataset_clean` из PostgreSQL. После очистки в ней осталось 131 940 квартир. Целевая переменная — `price` (стоимость квартиры в рублях).

Обработка данных и обучение организованы как DVC-пайплайн с четырьмя этапами:

| Этап | Команда | Результат |
|---|---|---|
| `export` | `python -m src.ml.export_data` | `data/ml/clean.csv` |
| `split` | `python -m src.ml.split_data` | `data/ml/train.csv`, `data/ml/test.csv` |
| `train` | `python -m src.ml.train` | `models/price_model.joblib` |
| `evaluate` | `python -m src.ml.evaluate` | `reports/metrics.json` |

Разделение выполнено с помощью `GroupShuffleSplit` по `building_id`. Квартиры из одного дома не пересекаются между обучающей и тестовой выборками. В обучающей выборке 105 578 квартир, в тестовой — 26 362.

## Модели

Для сравнения использованы три алгоритма:

- `DummyRegressor` с медианным прогнозом — простой ориентир для оценки качества.
- `Ridge` — линейная регрессия с регуляризацией. Пропуски числовых признаков заполняются медианой, затем признаки масштабируются. Категория `building_type_int` кодируется через one-hot.
- `CatBoostRegressor` — градиентный бустинг по деревьям. Дополнительно используются относительный этаж, доли жилой площади и кухни и площадь на комнату.

Предобработка Ridge обучается на тренировочной выборке. Для CatBoost число деревьев выбрано на внутренней валидации по домам, без использования тестовой выборки. После выбора числа деревьев итоговая модель обучается на всей обучающей части.

Параметры находятся в `params.yaml`. Состав шагов задан в `dvc.yaml`, контрольные суммы входов и выходов — в `dvc.lock`.

## Результаты

Оценка выполнена на 26 362 тестовых квартирах.

| Модель | MAE, ₽ | RMSE, ₽ | R² |
|---|---:|---:|---:|
| Прогноз медианы | 10 252 751,51 | 36 475 210,54 | −0,0426 |
| Ridge | 8 480 024,84 | 21 681 294,89 | 0,6316 |
| CatBoost | **4 205 322,58** | **15 843 854,69** | **0,8033** |

MAE CatBoost ниже результата Ridge на 50,4%. При этом абсолютная ошибка в рублях заметно зависит от стоимости объекта, поэтому результаты следует интерпретировать с учётом ценового диапазона квартир.

Метрики сохраняются в `reports/metrics.json` и доступны через `dvc metrics show`.

## Запуск

Нужны Python с зависимостями проекта, работающий PostgreSQL и локальный файл `.env` с переменной `POSTGRES_PASSWORD`. Для работы с DVC используется активированное виртуальное окружение.

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-stage3.txt
python -m dvc repro
python -m dvc metrics show
python -m dvc status
```

При неизменных входных файлах и параметрах `dvc repro` не обучает модель повторно. Если содержимое таблицы PostgreSQL изменилось, выгрузку нужно инициировать отдельно:

```powershell
python -m dvc repro -f export
```

Это необходимо, потому что DVC отслеживает файлы, код и параметры, но не изменения внешней базы данных.

## Хранение модели

Модель сохраняется в `models/price_model.joblib` и отслеживается DVC. Удалённое хранилище настроено на приватный бакет Yandex Object Storage:

- бакет: `yandex-realty-ml-2026`;
- префикс: `dvc`;
- S3 endpoint: `https://storage.yandexcloud.net`;
- регион: `ru-central1`.

Загрузка артефактов и проверка синхронизации:

```powershell
python -m dvc push
python -m dvc status -c
```

В Git хранятся код, `dvc.yaml`, `params.yaml`, `dvc.lock` и файл метрик. CSV-файлы и бинарная модель передаются через кэш DVC. Пароль PostgreSQL и ключи S3 остаются в локальном окружении и не включаются в репозиторий.
