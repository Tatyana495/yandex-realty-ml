# Yandex Realty — прогнозирование стоимости квартир

## писание проекта

Проект посвящён разработке MVP модели машинного обучения
для прогнозирования стоимости квартир по их характеристикам.

На первом этапе реализован ETL-процесс с использованием
Apache Airflow и PostgreSQL.

## Используемые технологии

- Python 3.12
- PostgreSQL 17
- Apache Airflow 3.3.2
- Docker Compose
- SQL
- pandas
- scikit-learn

## Исходные данные

Данные представлены двумя таблицами:

- buildings — характеристики домов.
- flats — характеристики квартир и их стоимость.

Связь таблиц:
flats.building_id = buildings.id

## ETL-процесс

DAG: real_estate_etl

Процесс состоит из четырёх задач:

1. create_table — создание итоговой таблицы.
2. extract — извлечение данных из исходных таблиц.
3. transform — объединение данных о квартирах и домах.
4. load — загрузка результата в PostgreSQL.

Для промежуточной обработки используются таблицы PostgreSQL.

## Результаты первого этапа

Исходные данные:

Итоговая таблица: real_estate_dataset

Результаты проверки:

## Запуск проекта

1. Установить Docker и Docker Compose.
2. Создать файл .env с переменной POSTGRES_PASSWORD.
3. Запустить PostgreSQL:

   docker compose up -d

4. Создать исходные таблицы с помощью create_tables.sql.
5. Загрузить исходные CSV-файлы в PostgreSQL.
6. Запустить Apache Airflow:

   docker compose -f compose.yaml -f compose.airflow.yaml up -d

7. Открыть Airflow:

   http://localhost:8081

8. Создать подключение real_estate_db:
   - Host: postgres
   - Port: 5432
   - Database: real_estate
   - User: real_estate_user
   - Password: из файла .env

9. Запустить DAG real_estate_etl.

## Этап 2. Очистка данных

### Цель этапа

Проверить объединённый датасет на дубликаты, пропуски, некорректные значения и выбросы. Разработать воспроизводимые функции очистки и автоматизировать их выполнение в Apache Airflow с сохранением результата в PostgreSQL.

### Анализ качества данных

В исходной таблице `real_estate_dataset` содержалось **141 362 квартиры**. Анализ проводился в Jupyter Notebook `notebooks/01_data_cleaning.ipynb`.

Были обнаружены:

- **9 116 повторных записей** по всем характеристикам, кроме `flat_id` (8 309 групп совпадений).
- Нулевые значения площадей кухни и жилой площади, рассматриваемые как скрытые пропуски.
- **135 записей с некорректными площадями**, в том числе с превышением суммы площадей над общей площадью квартиры и случаями, когда жилую площадь нельзя корректно восстановить.
- **171 ценовой выброс** по выбранным границам стоимости квадратного метра.

### Функции очистки

Функции реализованы в `src/cleaning.py` и вызываются последовательно через `clean_data()`:

1. **`remove_duplicates()`** — удаляет совпадающие по характеристикам записи, сохраняя для каждой группы квартиру с минимальным `flat_id`.
2. **`remove_invalid_areas()`** — исключает записи с противоречивыми площадями и случаи, когда площадь кухни занимает всю квартиру при отсутствующей жилой площади.
3. **`clean_missing_values()`** — заменяет нулевые значения площадей на `NaN`, заполняет их медианами по числу комнат, ограничивает сумму восстановленных площадей и сохраняет признаки `kitchen_area_missing`, `living_area_missing`.
4. **`remove_outliers()`** — рассчитывает стоимость квадратного метра и удаляет записи дешевле **20 000 руб./м²** и дороже **5 000 000 руб./м²**.

Ценовые пороги выбраны для учебного MVP после анализа распределения и метода межквартильного размаха (IQR). Они не являются универсальными рыночными границами. Удаление совпадающих по характеристикам квартир также может исключить разные реальные объекты, поскольку номера квартир в данных отсутствуют.

|---|---:|
| Исходный датасет | 141 362 |
| После удаления дубликатов | 132 246 |

| После удаления ценовых выбросов | **131 940** |

В итоговом датасете **131 940 строк и 20 столбцов**. Проверки показали отсутствие пропусков, повторяющихся идентификаторов, нулевых площадей и нарушений выбранных условий согласованности площадей. Целевая переменная `price` заполнена.

### Автоматизация в Airflow

DAG **`real_estate_cleaning`** содержит три задачи:

1. `check_source` — проверка исходной таблицы `real_estate_dataset`.
2. `clean_and_load` — применение функций очистки и запись результата.
3. `check_result` — проверка итоговой таблицы.

DAG выполнен успешно. Очищенный датасет сохранён в PostgreSQL в таблице **`real_estate_dataset_clean`**. Исходная таблица не изменена.

- `src/cleaning.py` — функции очистки, используемые в ноутбуке и DAG.
- `dags/real_estate_cleaning.py` — DAG автоматической очистки.

На втором этапе создан воспроизводимый процесс очистки данных. Из **141 362** исходных записей сохранено **131 940** квартир (удалено **9 422** записи). Очищенные данные готовы к следующему этапу — построению модели регрессии. ## тап 2. чистка данных

### ель этапа

ровести анализ данных о квартирах, выявить дубликаты,
пропущенные значения, логические ошибки и выбросы.
азработать функции очистки и автоматизировать их
выполнение с помощью Apache Airflow.

### лгоритм очистки данных

чистка реализована с помощью четырёх функций.

**1. remove_duplicates — удаление дубликатов**

- оиск записей с одинаковыми характеристиками квартир.
- Сравнение всех столбцов, кроме flat_id.
- Сохранение записи с минимальным flat_id.

**2. remove_invalid_areas — проверка площадей**

- оиск квартир с некорректными значениями площадей.
- даление записей, в которых сумма жилой площади
  и площади кухни превышает общую площадь.
- даление квартир, у которых невозможно корректно
  восстановить отсутствующую жилую площадь.

**3. clean_missing_values — обработка пропусков**

- амена нулевых значений площадей на NaN.
- аполнение пропусков медианными значениями
  с учётом количества комнат.
- Создание признаков, показывающих наличие
  пропусков в исходных данных.
- роверка согласованности площадей после заполнения.

**4. remove_outliers — обработка выбросов**

- асчёт стоимости одного квадратного метра.
- нализ распределения цен и метода IQR.
- даление квартир со стоимостью квадратного метра
  менее 20 000 рублей.
- даление квартир со стоимостью квадратного метра
  более 5 000 000 рублей.

ыбранные ценовые границы являются эвристическими
порогами для учебного MVP.
